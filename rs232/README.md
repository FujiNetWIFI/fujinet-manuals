# The RS-232 FujiNet User's Manual

A platform-neutral user's manual for the **RS-232 FujiNet**: how to set the
adapter up with `fnconfig.ini`, the FujiBus (FEP-004) packet byte by byte,
the rules of a transaction, a command reference for every device on the bus
(Fuji, disk, network, clock, printer, modem, CP/M), each command shown with a
real request and reply, and three complete Z80 programs for an **Altair 8800
with a MITS 88-2SIO** — CONFIG, NETCAT and a FujiNet 5 Card Stud client —
built on a small FujiBus library whose hardware code is fenced off between
`PLATFORM BEGIN` / `PLATFORM END` markers for porting.

It is typeset in the **FujiNet engineering series** house style (The FujiNet
Network Protocol Handbook, the Platform Bring-Up Guide, the ColecoVision
Programmers Handbook): single-column US-Letter, Nimbus Roman body, Nimbus Sans
heads, Source Code Pro listings, FujiNet-red accents, sticky headings, and
strict widow/orphan control.

## Building

Requires [Typst](https://typst.app) 0.15 or newer.

```sh
make            # -> fujinet-rs232-users-manual.pdf (124 pp)
make check      # margin/stranded-head/short-page/widow checks + pdffonts
make preview    # PNG per page at 110 ppi, into preview/
make listings   # assemble every Z80 program (needs z88dk-z80asm)
make wiki       # regenerate the wiki edition from its template
make examples   # re-capture examples.json from a running fujinet-pc
```

Fonts ship in `fonts/`: Nimbus Roman, Nimbus Sans, Source Code Pro.
`pdffonts` should list only those three families.

## How the byte streams are made

Every request/reply drawn in the book is read from `examples.json`, which
`tools/examples.py` captures from a running fujinet-pc built for the RS-232
target from `fujinet-firmware` (BoIP on port 1985). The script resets the
host and disk slots first, so a re-capture reproduces the same bytes (apart
from the clock, the random number and the GUID). It needs these files in the
fujinet-pc SD directory: `test/disk.img` (any size, multiple of 512),
`test/readme.txt`. A few commands are not sent (RESET, SET_BOOT_MODE,
SETTZ_ALT); their requests are computed and marked "not sent".

`tools/fujibus.py` is a small Python FujiBus client (encode, decode, SLIP,
checksum, `Bus.call`) usable on its own; `tools/httpget.py` fetches a URL
through `N:`.

## The example programs

All in `listings/`, `ORG 0100h`, no CP/M calls (assemble with `-DCPM=1` to
return to CP/M), verified on SIMH AltairZ80 against fujinet-pc:

| Program | File | What it shows |
|---|---|---|
| library | `common/altair.inc`, `fujibus.inc`, `conio.inc` | 88-2SIO platform layer, FujiBus framing/retry/RESEND, console helpers |
| HELLO | `hello/hello.asm` | first contact: WiFi status, host slots |
| CONFIG | `config/fncfg.asm` | host slots, browse + mount, eject, WiFi |
| NETCAT | `netcat/netcat.asm` | TCP/TELNET terminal |
| 5 CARD STUD | `5cs/stud.asm` | HTTPS game client, binary state, Teletype-friendly output |

`session.txt` beside each is the captured terminal session printed in the
book. `sim/` runs them: `sim/run.sh <program.bin> [--keys "..."]` starts
AltairZ80 (`sim/altair.ini`), bridges 88-2SIO port B to fujinet-pc with
`socat`, and drives port A with `sim/term.py`; `FAULT=n` routes the traffic
through `tools/faultproxy.py`, which damages every nth reply to exercise the
retry and RESEND paths.
